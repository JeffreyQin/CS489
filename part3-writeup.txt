Part 3.1 unsmoothed n-gram model

part3_ngram_lm.py trains a maximum-likelihood n-gram model on the BPE token ids of the cleaned training lines. Each line is encoded on its own with the submitted 50,000-token byte-BPE model, then the end-of-line token EOS (id 50,000) is appended and scored with the other tokens. N-grams do not cross lines. No beginning-of-line token is used, so the first token of a line is predicted from the empty context, P(w) = C(w) / N, and later tokens use only as much history as the line has, up to n - 1 tokens. The estimate is the raw count ratio C(context, w) / C(context). There is no smoothing.

The training data has 24,571,928 scored tokens, EOS included. Every order still assigns probability 0 to at least one dev token, and one zero factor makes the product over the dev set zero, so perplexity is infinite.

For order 2 the first zero is the bigram (15333, 2376), the pieces " 29" and " آ". That pair occurs in the dev text and never occurs in the training counts, so P(" آ" | " 29") = 0.

For orders 3, 4, and 5 the first zero is the same trigram, (1912, 12896, 1375), the pieces "29", " مارس", and " أو". It is the third token of a dev line, so even the order-4 and order-5 models are only conditioning on the two tokens of history that exist there. The trigram is absent from training, so that conditional probability is 0. A larger order does not remove the zero: the shorter history is already unseen, and an unsmoothed model has no backoff and no reserved mass for novel n-grams.

Part 3.2 add-alpha smoothing

With add-alpha smoothing the same counts are turned into

P(w | context) = (C(context, w) + alpha) / (C(context) + alpha * V),

where V = 50,001 is the 50,000 BPE tokens plus EOS. An unseen token keeps probability alpha / (C(context) + alpha * V) instead of zero, so dev perplexity is finite.

Alpha was tuned on the full cleaned dev set. Orders 2, 3, 4, and 5 were each scored on a log grid from 1e-7 to 1, and order 2 was then searched in steps of 0.0002 from 0.001 to 0.008. The minimum is order 2 with alpha = 0.004, dev perplexity 860.018. The neighbors 0.0038 and 0.0042 are 860.054 and 860.241, so the bottom of the curve is flat.

Longer contexts are worse under this smoother, not better. At the best alpha for each order, dev perplexity is about 860 for order 2, about 4,520 for order 3, about 13,900 for order 4, and about 21,200 for order 5. Most long contexts occur once or not at all, and alpha * V is hundreds of counts when alpha is large enough to cover novel events, so the extra history is washed out. A bigram still has enough repeated counts that a small alpha fixes the zeros without flattening the distribution.

Part 3.3 selection

Bits per character on the dev set is (T / N_chars) * log2(perplexity), with T = 2,491,425 scored tokens (one EOS per line included) and N_chars = 7,516,387 characters in the cleaned dev text. T and N_chars do not depend on n or alpha, so the ranking by perplexity and the ranking by bits per character are the same.

The submitted model is the minimum: order 2, alpha = 0.004, no BOS token, vocabulary size 50,001. Dev perplexity is 860.018 and dev bits per character is 3.231. part3.py writes that model to artifacts/part3/model.json.gz.

Orders 3–5 lose because add-alpha has no backoff. A context that was seen once gets a denominator of about 1 + alpha * 50,001, so the longer gram is close to uniform over the whole vocabulary. Bigram counts are dense enough that alpha = 0.004 removes the zeros (the unsmoothed dev perplexity was infinite) without drowning the counts that were actually observed.

Part 3.4 analysis

The model is the one trained on all seven languages together. For each language's own cleaned dev.txt, and for each order n from 2 to 5, alpha was tuned on that file and the best token perplexity was kept. The curves are in artifacts/part3/perplexity_vs_n.svg. The y-axis is logarithmic.

(a) Every language has the same shape. Perplexity is lowest at n = 2 and rises at every larger order. From bigrams to trigrams it jumps by about four to six times, and by n = 5 it is roughly twenty to forty times the bigram value. A longer history does not help under add-alpha. The extra context is usually new: the share of dev tokens whose n-gram was never seen in training is about 16–26% at n = 2, 56–71% at n = 3, and 80–88% at n = 5. Those predictions are carried by the smoothing term, which is close to uniform over 50,001 tokens, so perplexity climbs toward the size of the vocabulary.

The languages differ in height, not in the direction of the curve. At n = 2 the best perplexities are Russian 534, Hungarian 622, Finnish 665, Vietnamese 732, Arabic 798, German 854, and Mandarin 1,495. Mandarin stays the top curve through n = 5 (26,208). About 26% of its bigrams are unseen, against about 17% for Finnish, Hungarian, and Russian, and 71% of its trigrams are unseen. Its BPE pieces are short, and many of them do not repeat as pairs, so the next token is harder to pin down from one preceding token.

Hungarian, Russian, and Finnish sit lowest, and Hungarian still has the smallest unseen rate at n = 5 (80%, against 88% for Arabic). Repeated word-internal pieces, including suffixes, show up as reused tokens. That advantage is real and small. It does not bend the curve downward: even Hungarian trigrams are worse than Hungarian bigrams (2,363 against 622). Vietnamese, which is isolating, tracks the alphabetic languages rather than Mandarin. After BPE, what matters for these curves is how often a token sequence repeats, which follows the spelling as much as the morphology.

The curves also draw together as n grows. At n = 2 Mandarin is about 2.8 times Russian; at n = 5 it is about 1.6 times Hungarian, the lowest curve there. Once most contexts are unseen, every language is scored by nearly the same fallback and the linguistic differences shrink.

Smoothing is already required at n = 2, because an unsmoothed model is infinite as soon as one dev n-gram is missing, and every language has some. It is most important at the largest n. That is where 80% or more of the predictions have a zero count, so the tuned alpha, not the training counts, is what produces the probability. The tuned alpha itself shrinks with n (about 0.002–0.008 for bigrams, 0.0003 for trigrams, and about 0.0001 for orders 4 and 5). A larger alpha would flatten the few long grams that were seen. The smaller one does not make those orders good; it only limits how flat they get.

(b) A larger BPE vocabulary makes smoothing more important. The training text is fixed, so more token types means the same counts are spread over more n-grams. Each one is rarer, and a dev token is more likely to land on an n-gram that never occurred. Maximum likelihood is then infinite. Add-alpha stays defined, but its denominator contains alpha times V, so a bigger vocabulary also makes the smoothing term larger relative to the observed counts. A small character vocabulary repeats trigrams often enough that smoothing is a minor correction. At V = 50,000 the correction is what keeps bigram probabilities finite, and by n = 4 or 5 it is most of the probability. Byte-level BPE still has no unknown byte, but the larger set of learned pieces creates rare combinations, and those combinations are exactly what the smoother has to cover.
