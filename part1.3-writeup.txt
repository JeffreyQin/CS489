Part 1.3 encoder and decoder

part1.3-encode.py loads bpe_vocab.txt and bpe_merges.txt and encodes one file into token ids, one decimal id per line. Each input byte is already a base token (id 0 through 255). The script then applies the learned merges in the order they were learned, inside each line, and writes token id 10 for each newline. part1.3-decode.py looks each id up in the vocabulary and writes the stored bytes. Running the two scripts back to back on a cleaned file reproduces that file byte for byte.

Byte-level BPE has no out-of-vocabulary problem because the base vocabulary contains every byte value from 0 to 255. Any file is a sequence of those bytes, including a character, emoji, or script that never appeared in training. Encoding always starts from in-vocabulary symbols, and decoding concatenates the byte strings stored for those token ids, so the original bytes come back exactly. There is no unknown token and nothing is dropped.

Character-level BPE is different. Its base vocabulary is only the characters that showed up in the training text. A character that was absent has no token. The usual fix is an unknown-token id, and that id does not remember which character it replaced, so the original text cannot be reconstructed. Byte-level BPE avoids that case entirely: every possible input is already covered by the 256 base tokens.
